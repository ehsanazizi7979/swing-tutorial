How to use this guide

Read the bold line first — it is the one thing the lesson is really about. The bullets explain the code, and the Key APIs chips are the class names to search for when you are writing your own version.

Use the search box for a class (try SwingWorker or GridBagLayout), tick lessons as you finish them, and press Ctrl/Cmd+P if you want a printable copy.

A quick heads-up

  • The course was recorded around 2012. In modern JDKs, replace ActionEvent.CTRL_MASK with InputEvent.CTRL_DOWN_MASK, and the MySQL driver class with com.mysql.cj.jdbc.Driver.
  • Applets (lessons 73–85) no longer run in browsers, but the drawing, timer, and animation skills transfer directly to desktop windows.
  • Database lessons need MySQL plus the schema in mysql_database.sql. Use your own credentials instead of the sample ones.

Lessons 1–11

Foundations

Windows, layout managers, buttons, custom panels, and your first form.

01

Lesson 1: Hello World

Create and show your first window.

  • A JFrame is the main window of a Swing app. Give it a title, then call setSize, setDefaultCloseOperation, and setVisible(true).
  • Start Swing code on the Event Dispatch Thread with SwingUtilities.invokeLater(...). That is the thread that safely handles all GUI work.
  • EXIT_ON_CLOSE ends the whole program when the window is closed, not just the window.
  • An empty frame is normal at this stage. Components come next.
Key APIsJFrameSwingUtilities.invokeLatersetDefaultCloseOperation

Lesson 2: BorderLayout and Text Areas

Split the window into regions and add a scrollable text area.

  • A frame's content area uses BorderLayout by default. CENTER takes the leftover space; NORTH, SOUTH, EAST, and WEST hug the edges.
  • JTextArea holds multiple lines of plain text. Wrap it in a JScrollPane so long text can scroll.
  • MainFrame extends JFrame keeps App tiny and makes the screen reusable.

Lesson 3: Button Clicks

Make a button actually do something.

  • Attach behavior with addActionListener(new ActionListener() { ... }).
  • The actionPerformed(ActionEvent e) method runs whenever the button is pressed.
  • textArea.append("Hello\n") adds text without erasing what is already there.

Build your own reusable panel.

  • TextPanel extends JPanel wraps the text area and its scroll pane, so other classes do not need to know those details.

  • The frame now works with TextPanel, not JTextArea. That makes the UI easier to change later.

Lesson 11: GridBagLayout

Lay out labels and fields in a grid that can stretch.

  • GridBagLayout plus GridBagConstraints places each component at gridx / gridy.
  • weightx and weighty decide who gets extra space; fill and anchor control stretching and alignment.
  • insets adds spacing. Insets(0, 0, 0, 5) leaves a gap between a label and its field.
  • It is wordy, but precise. This becomes the main form layout for the rest of the course.

Lesson 36: Connecting to Databases

Connect Swing to MySQL with JDBC.

  • connect() returns early if already connected; disconnect() closes the connection.
  • TestDatabase is a small main program for testing the connection without the GUI.

Note Needs a running MySQL server and the schema from mysql_database.sql. Use your own database user and password.

Lesson 37: Getting Values from Databases

Ask the database whether a person already exists.

  • Person ids now start at 1 so they match database ids.

Lesson 38: Inserting Values into Databases

  • executeUpdate() performs the change, and statements are closed when finished.

Lesson 39: Updating Databases

Update rows that already exist.

  • Set the new values first and the id last, because it is the final ?.
  • The count check chooses the path: 0 means insert, anything else means update.
  • Both paths call executeUpdate() so the database stays in sync with the list.

Lesson 55: Swing Multithreading

Lesson 66: Setting Fonts

Change text size and style.

  • new Font("Serif", Font.PLAIN, 20) creates a font; textArea.setFont(...) applies it.

The big picture

Ten habits that unlock Swing

If you remember nothing else from the 86 lessons, remember these.

01

Build on the EDT. Start with SwingUtilities.invokeLater; long work belongs in a SwingWorker, never on the Event Dispatch Thread.

02

Compose, don't inherit. One small JPanel subclass per screen area beats one giant frame class.

03

Talk through listeners. Custom events such as StringListener and FormListener keep components independent.

04

Pick the right layout. BorderLayout for regions, GridBagLayout for forms, FlowLayout for button rows.

05

The model is the truth. Tables, lists, and trees ask a model; they do not store your data themselves.

06

Separate view, model, controller. The gui package should not contain your business rules or SQL.

07

Renderers vs editors. A renderer controls how a value looks; an editor controls how it is changed.

08

Dialogs have jobs. JOptionPane for quick questions, JFileChooser for files, JDialog for custom screens.

09

Close what you open. Statements, connections, streams, and windows: clean up in close handlers and finally blocks.

10

Draw less, repaint smarter. Keep state in fields, change it in update(), repaint, and double-buffer to avoid flicker.

Plain-English glossary

The words that keep coming back

Short definitions for the jargon the lessons use.

Event Dispatch Thread (EDT)

The single thread that runs Swing painting and input. Touching components from other threads causes strange bugs.

Layout manager

An object that decides where components go and how they resize. BorderLayout, FlowLayout, and GridBagLayout are the main ones here.

Listener

An interface you implement to be notified when something happens, such as a click, a selection, or a custom form event.

Model

The object that holds data for a widget. A table model answers "how many rows?", "what is in this cell?", and "is this cell editable?".

Renderer

A component that paints one cell, row, or tree node. It is reused and only displays values; it does not store them.

Editor

A component that lets the user change a value in a cell or node, usually a text field, combo box, or check box.

JDBC

Java's standard API for talking to databases: driver, Connection, PreparedStatement, and ResultSet.

Serialization

Turning live objects into bytes so they can be saved to a file, and reading them back later. Requires Serializable.

SwingWorker

A helper for background work. Slow code goes in doInBackground, progress comes back through publish/process, and the result arrives in done.

Double buffering

Drawing into an off-screen image first, then showing it in one go. It removes flicker during animation.

CardLayout

A layout that stacks components like cards and shows exactly one at a time — handy for start screens and game states.

Preferences

A small built-in key/value store for user settings, provided by java.util.prefs.Preferences.
