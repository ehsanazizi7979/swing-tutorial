Lesson 1: Hello World

Create and show your first window.

  • A JFrame is the main window of a Swing app. Give it a title, then call setSize, setDefaultCloseOperation, and setVisible(true).
  • Start Swing code on the Event Dispatch Thread with SwingUtilities.invokeLater(...). That is the thread that safely handles all GUI work.
  • EXIT_ON_CLOSE ends the whole program when the window is closed, not just the window.
  • An empty frame is normal at this stage. Components come next.
▸Code exampleApp.java 
SwingUtilities.invokeLater(new Runnable() {
    public void run() {
        JFrame frame = new JFrame("Hello World");
        frame.setSize(600, 500);
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        frame.setVisible(true);
    }
});

Lesson 4: Custom Components

Build your own reusable panel.

  • TextPanel extends JPanel wraps the text area and its scroll pane, so other classes do not need to know those details.
  • Keep components private and expose only useful behavior, like appendText(String).
  • The frame now works with TextPanel, not JTextArea. That makes the UI easier to change later.
▸Code exampleTextPanel.java 
public class TextPanel extends JPanel {

    private JTextArea textArea;

    public TextPanel() {
        textArea = new JTextArea();
        setLayout(new BorderLayout());
        add(new JScrollPane(textArea), BorderLayout.CENTER);
    }

    public void appendText(String text) {
        textArea.append(text);
    }
}

Lesson 6: Communication

Let the toolbar update the text panel.

  • Toolbar implements ActionListener, so one actionPerformed method handles both buttons.
  • e.getSource() tells you which button was clicked; cast it to JButton to compare.
  • Passing a TextPanel into the toolbar works, but it tightly couples the two classes. Lesson 7 fixes that.
▸Code exampleToolbar.java 
public void actionPerformed(ActionEvent e) {
    JButton clicked = (JButton)e.getSource();

    if(clicked == helloButton) {
        textPanel.appendText("Hello\n");
    }
    else if(clicked == goodbyeButton) {
        textPanel.appendText("Goodbye\n");
    }
}

Lesson 11: GridBagLayout

Lay out labels and fields in a grid that can stretch.

  • GridBagLayout plus GridBagConstraints places each component at gridx / gridy.
  • weightx and weighty decide who gets extra space; fill and anchor control stretching and alignment.
  • insets adds spacing. Insets(0, 0, 0, 5) leaves a gap between a label and its field.
  • It is wordy, but precise. This becomes the main form layout for the rest of the course.
▸Code exampleFormPanel.java 
setLayout(new GridBagLayout());
GridBagConstraints gc = new GridBagConstraints();

gc.gridx = 0;
gc.gridy = 0;
gc.weightx = 1;
gc.weighty = 0.1;
gc.anchor = GridBagConstraints.LINE_END;
gc.insets = new Insets(0, 0, 0, 5);
add(nameLabel, gc);

gc.gridx = 1;
gc.anchor = GridBagConstraints.LINE_START;
gc.insets = new Insets(0, 0, 0, 0);
add(nameField, gc);

Lesson 12: Events

Send a whole form's data as one custom event.

  • Create FormEvent (source plus the field values) and FormListener with formEventOccurred(FormEvent).
  • FormPanel reads its fields, builds the event, and calls its listener. It never writes to the text area itself.
  • MainFrame implements the listener and decides what to do with the data.
  • Custom events keep the form reusable and independent from the screen that uses it.
▸Code exampleFormListener.java 
public interface FormListener {
    void formEventOccurred(FormEvent e);
}

// FormPanel: announce the data, don't display it
FormEvent ev = new FormEvent(this, name, occupation);

if(formListener != null) {
    formListener.formEventOccurred(ev);
}

Lesson 20: Mnemonics and Accelerators

Add keyboard shortcuts.

  • A mnemonic is an underlined letter: setMnemonic(KeyEvent.VK_O) makes Alt+O activate the control.
  • A label can forward focus with setDisplayedMnemonic(...) plus setLabelFor(field).
  • An accelerator is a global shortcut: KeyStroke.getKeyStroke(KeyEvent.VK_X, ActionEvent.CTRL_MASK) gives Ctrl+X.
▸Code exampleFormPanel.java

fileMenu.setMnemonic(KeyEvent.VK_F);

public class PersonFileFilter extends FileFilter {

    public boolean accept(File file) {
        if(file.isDirectory()) return true;

        String extension =

        return "per".equals(extension);

        return "Person database file (*.per)";
    }
}

Lesson 25: Controller

One class that turns form input into a Person.

  • Controller receives a FormEvent and converts strings and ids into typed enums: a switch for age, equals checks for employment and gender.
  • db.addPerson(person) stores the result; the frame only calls controller.addPerson(e).
  • This is the start of MVC: view (Swing), model (data), and controller (decisions).
▸Code examplecontroller/Controller.java 
public void addPerson(FormEvent ev) {
    int ageCatId = ev.getAgeCategory();

    AgeCategory ageCategory = null;
    switch(ageCatId) {
    case 0: ageCategory = AgeCategory.child;  break;
    case 1: ageCategory = AgeCategory.adult;  break;
    case 2: ageCategory = AgeCategory.senior; break;
    }

    EmploymentCategory empCategory =
            EmploymentCategory.employed;  // simplified
    Gender genderCat = Gender.male;       // simplified

    Person person = new Person(ev.getName(),
            ev.getOccupation(), ageCategory,
            empCategory, ev.getTaxId(),
            ev.isUsCitizen(), genderCat);

    db.addPerson(person);
}

▸Code exampleGame.java 
private Ellipse2D.Double ball =
        new Ellipse2D.Double(100, 100, 15, 15);
private double speed = 10.0;
private int xDirectionBall = 1;

public void update() {
    ball.x += xDirectionBall * speed;

    if(ball.x < 0) {
        xDirectionBall = 1;
        ball.x = 0;
    }
    else if(ball.x > getWidth() - ball.getBounds().width) {
        xDirectionBall = -1;
        ball.x = getWidth() - ball.getBounds().width;
    }

    repaint();
}

The big picture

Ten habits that unlock Swing

If you remember nothing else from the 86 lessons, remember these.

01

Build on the EDT. Start with SwingUtilities.invokeLater; long work belongs in a SwingWorker, never on the Event Dispatch Thread.

02

Compose, don't inherit. One small JPanel subclass per screen area beats one giant frame class.

03

Talk through listeners. Custom events such as StringListener and FormListener keep components independent.

04

Pick the right layout. BorderLayout for regions, GridBagLayout for forms, FlowLayout for button rows.

05

The model is the truth. Tables, lists, and trees ask a model; they do not store your data themselves.

06

Separate view, model, controller. The gui package should not contain your business rules or SQL.

07

Renderers vs editors. A renderer controls how a value looks; an editor controls how it is changed.

08

Dialogs have jobs. JOptionPane for quick questions, JFileChooser for files, JDialog for custom screens.

09

Close what you open. Statements, connections, streams, and windows: clean up in close handlers and finally blocks.

10

Draw less, repaint smarter. Keep state in fields, change it in update(), repaint, and double-buffer to avoid flicker.

Plain-English glossary

The words that keep coming back

Short definitions for the jargon the lessons use.

Event Dispatch Thread (EDT)

The single thread that runs Swing painting and input. Touching components from other threads causes strange bugs.

Layout manager

An object that decides where components go and how they resize. BorderLayout, FlowLayout, and GridBagLayout are the main ones here.

Listener

An interface you implement to be notified when something happens, such as a click, a selection, or a custom form event.

Model

The object that holds data for a widget. A table model answers "how many rows?", "what is in this cell?", and "is this cell editable?".

Renderer

A component that paints one cell, row, or tree node. It is reused and only displays values; it does not store them.

Editor

A component that lets the user change a value in a cell or node, usually a text field, combo box, or check box.

JDBC

Java's standard API for talking to databases: driver, Connection, PreparedStatement, and ResultSet.

Serialization

Turning live objects into bytes so they can be saved to a file, and reading them back later. Requires Serializable.

SwingWorker

A helper for background work. Slow code goes in doInBackground, progress comes back through publish/process, and the result arrives in done.

Double buffering

Drawing into an off-screen image first, then showing it in one go. It removes flicker during animation.

CardLayout

A layout that stacks components like cards and shows exactly one at a time — handy for start screens and game states.

Preferences

A small built-in key/value store for user settings, provided by java.util.prefs.Preferences.
